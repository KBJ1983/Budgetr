## Architecture

- `/` landing page (Next.js, `components/landing/`), `/login` test-user login (Next.js), `/app` = the ORIGINAL budgetr app from the prototype, a single vanilla-JS file at `public/budgetr-app/index.html` (rewritten in `next.config.ts`). The user chose to keep that app 1:1 instead of a React rebuild; change features by editing that file directly, and keep its behaviour and look.
- Vendor libs for the app live in `public/budgetr-app/vendor/` (jsPDF, AutoTable, xlsx-js-style = SheetJS 0.18.5 with cell styles, `pdfjs/` = pdf.js 6.3.289 legacy build for reading PDF statements, loaded on first use). Don't edit them.
- Draft budgets (Kladder): whole budgets stored inside the primary one as `drafts[]` (`{id,name,created,mode,files,data}`, one level deep). While a draft is open, `S` is the draft's data and `ROOT` the primary budget, so all pages work on the draft; saving and the backup always use `rootS()`. The draft import reads several CSV/Excel/PDF statements at once, pairs transfers between the uploaded accounts, and stores only the chosen entries (never the transactions). "Sæt som primært budget" swaps them and keeps the old budget as a draft (`mode:'prev'`). The guide "Start nyt budget" also saves its result as a draft when a budget already exists; it only becomes the primary budget on a first visit.
- Test-user layer: `lib/users.ts` (KBJ, TEST1–TEST5, no password). `/login` writes the user id to `localStorage["budgetr:session"]`; the prelude script at the top of the app's `<head>` reads it, redirects to `/login` without it, and stores the budget under `budgetr-app:<userId>`. To add a user, append to `USERS`.
- Demo customer: test user `demo` (login `DEMO`, no mail). `/demobruger` (`components/app/OpenDemo.tsx`) resets its budget through `POST /api/demo` to the fictional family in `lib/demo-customer.ts` (every feature in use: all three draft kinds, scenarios, goals, loans, history, tasks, reminders), clears the browser copy and opens `/app`. Logging in with `DEMO` on `/login` keeps the changes instead. When the app gets a new feature, add it to the demo.
- Real accounts (next to the test users): `/opret` takes first name, last name, e-mail and a Danish mobile number and mails a confirm mail; later logins also go by mail (no passwords). Each mail has a link (logs in the device that opens it) and a 6-digit code (typed on the device that asked, max 5 tries). `lib/signup.ts` (form rules, shared with the browser), `lib/accounts.ts` (`data/accounts/<id>.json`, ids `u-…`, one-time links stored as a hash), `lib/session.ts` (signed httpOnly cookie `budgetr_session`; `/api/budget` and `/api/profile` serve an account only to its own session, test users need none), `lib/auth-mail.ts`, routes `app/api/auth/*`, link page `/login/bekraeft` (the link is only used on a button press, so mail scanners can't spend it). Confirming writes `data/profiles/<id>.json` for reminders. The app also keeps the name in `localStorage["budgetr:session-name"]`.
- Shared budgets: an account's own e-mail is the primary login; the primary can add up to 2 more e-mails (`MAX_LOGINS = 3`) under Indstillinger > Deling (route `app/api/members/[user]`). Members are stored in the account file (`members[]`), get an invite mail (link, 7 days) and later their own login codes; one e-mail belongs to one budget only. A member's session cookie carries the member id, so removing a member (or the member leaving) ends their access. Reminders still go to the primary's profile.
- "Send på mail" (Import og eksport): the app builds the PDF/Excel file and posts it to `app/api/send/[user]`; `lib/send-file.ts` checks it (own file types only, ≤3 MB, one receiver, max 10 mails a day per budget) and mails it through Resend with the sender's name and reply-to. Only real accounts with a session may send; test users only in development.
- Owner overview `/admin` (`components/owner/OwnerDashboard.tsx`, route `app/api/owner`): users, active users, paying users, MRR, next month's revenue (renewals, plans that end, trials that end), expenses, a 12-month forecast and the customer categories Banker / Ejendomsmæglere / Skoler / Privatpersoner. No payment provider yet: plans, firmaaftaler (organisations that accounts are linked to) and expenses are kept by hand in `owner/ledger.json`. Calculations in `lib/owner.ts` (no server imports, used by the browser too), storage + access in `lib/owner-store.ts`. Active users come from `activity/<id>.json`, noted by `/api/budget` (once an hour per login). Access: `/admin` shows a login (e-mail from `OWNER_EMAILS` + the fixed `ADMIN_PASSWORD`, ≥12 chars; route `app/api/admin/login`, signed httpOnly cookie `budgetr_admin`, 7 days, max 8 wrong tries per 15 min); a mail-login session of an account whose e-mail is in `OWNER_EMAILS` also works. `/api/owner` answers 404 to everyone else. Open without login in development unless `ADMIN_PASSWORD` is set. Never commit the owner's e-mail or password – they live only in env. Keep `PRICES` in step with `components/landing/PricePlans.tsx`.
- Aftaler (plan `docs/plans/2026-10-13-aftaler-adgang.md`, steps 1–3 done): a firmaaftale (`Org` in the owner ledger) has up to 5 kundeadmins (`admins`, e-mails) and packs of seats (`packs`: X seats × Y months, bought once, sendable until `sendBy`), edited on `/admin`; new kundeadmins get a mail with a link to `/aftale` (also when a colleague adds them). `lib/agreements.ts` hands seats out by e-mail as grants (`aftaler/<orgId>/adgange/`): send, send again (same code, max 3 a day), withdraw an unused one, take a seat with the code (months count from that day). Nobody ever sees a code – not the kundeadmin, not the owner, no API: it is derived from the grant id with the session key and only its hash is stored; the seat mail (`lib/agreement-mail.ts`) is the only place it is shown. `/aftale` is the kundeadmins' page (`components/aftale/`, one route `app/api/aftale` for all actions, login by mailed code/link like the teachers: `lib/agreement-admins.ts`, cookie `budgetr_aftale`, link page `/aftale/bekraeft`); who is kundeadmin is read from the ledger on every request, so taking the e-mail off ends the access. The seat mail links to `/aftale/brug?kode=…`, which sends teachers to Skole and customers to `/opret`/`/login` with the code. Skole (step 3, `lib/skole-seats.ts`): only a teacher with a seat can make classes (`POST /api/skole/klasse` answers 403 without); the seat is taken with the code (`/api/skole/plads`), or at once on `/skole/laerer` when a seat waits for the teacher's e-mail; `Teacher.seat` only counts while the grant is still theirs, and a school's kundeadmin can take it back on `/aftale` ("Fjern lærer"). A teacher without a seat sees the demo class `/skole/klasse/demo` (made-up pupils in `lib/skole-demo.ts`, nothing stored) and can ask a school with an agreement for a seat (mail to its kundeadmins, once a day). Teachers who signed up before 14.10.2026 make classes without a seat until 1.8.2027 (`EARLY_TEACHERS_*`). Taking a seat as a bank/estate-agent customer is step 4.
- Three front doors: Privat (`budgetpro.dk`), Erhverv (`erhverv.<domain>`) and Skole (`skole.<domain>`), with a small "Privat · Erhverv · Skole" switch above the dark top card of each front page (`components/SiteSwitch.tsx`, addresses from `lib/site-host.ts`: subdomains on the real domain, `/erhverv` and `/skole` on localhost / IPs / `*.vercel.app`). On `erhverv.<domain>` `proxy.ts` serves `/erhverv` at the root and redirects every other path to the main site; `/erhverv` on the main domain redirects to the subdomain. The Erhverv page (`components/erhverv/`, landing styles + `SiteHeader`/`SiteFooter` with own links) is kept short: the hero says what budgetpro is (meeting photo `public/erhverv/foto-moede.jpg`), then `Explainer` (a placeholder for a small animation about budgetpro Erhverv, with its three beats as text), the sectors and the price calculator, and only after that the landing page's feature band (`Features` with its own head, "Det får kunderne med budgetpro"), other sectors, trust and FAQ. At the bottom is a price calculator + price request in one form (`PriceRequest.tsx`, `lib/erhverv.ts`, route `app/api/erhverv/kontakt`): the price shows a month by default (`packMonthly()`) and switches to a year (`packYearly()`; "Samlet" for packs under 12 months), the choice is sent as `billing`, and the page says plainly that it is only a price request and no agreement is made. It saves each henvendelse as `erhverv/henvendelser/*.json` in the store and mails `OWNER_EMAILS` (max 3 a day per e-mail, 50 in all, honeypot field `website`). The form asks for the sector (bank / ejendomsmægler / andet) and a pack of codes from the price list in `lib/erhverv-packs.ts` ("model A": X codes × 3/6/12/24 months, paid once, cheaper per code with more codes and months; "Vi vil hellere tale om det" is allowed) and says the pack can always be changed – it stays direct contact, no self-serve signup. Each henvendelse waits under "Henvendelser" on `/admin` (`lib/erhverv-inbox.ts`) until the owner presses "Opret som kunde" (one dialog shows what they picked and wrote, with name, category, kundeadmin, note and the first pack at list price filled in; agreement and pack are saved together) or "Marker som klaret". The owner's mail and the /admin card list every choice from the price calculator through `inquiryChoices()` in `lib/erhverv.ts`. Keep the FAQ price example on the Erhverv page in step with `packPrice()` / `packMonthly()`. The private front page has a short Erhverv teaser (`BusinessTeaser`) before the final call to action.
- budgetpro Skole (`/skole`; on its own subdomain `skole.<domain>` through `proxy.ts` + `lib/skole-host.ts`, which serve `/skole/…` from the root there and block the rest of the site): a simple school version from the sketch `docs/design/skole-skitse.html` (layout), in the Skole brand "Midnat og solgul" (`docs/design/skole-21b.html`, see Brand). The root is the front page (`components/skole/landing/`, design "Skole forside", Oct 2026; its laptop/phone show real screenshots in `public/skole/`, made by `pnpm shots:skole` with the dev server up – rerun after visible changes to the pupil pages). Pupils type their code on `/elev` (the printed code slips point there) and make a month budget for a fictional young adult in 8 steps, then a summary (PDF) and "Mit budget" (`components/skole/`; cases, texts and all numbers in `lib/skole.ts`). Teachers have their own logins, apart from the budget accounts: `/skole/laerer` signs up (name, school, e-mail) or logs in with a mailed 6-digit code or link (`lib/skole-teachers.ts`, mail text `lib/skole-mail.ts`, routes `app/api/skole/auth/*`, link page `/skole/laerer/bekraeft`, signed httpOnly cookie `budgetr_skole` in `lib/session.ts`, `lib/skole-auth.ts` for "who is logged in"). Logged in, `/skole/laerer` is "Mine klasser": make a class (grade, pupils, 30/60/90 days) and see every live class with its codes; `/skole/klasse/<id>` is the class (only its own teacher can open it) with the expiry date, codes (copy/print), the pupils' progress and, per code, the choices and reflection answers (`pupilDetail()`); pupils are told the teacher reads them and not to write names. `lib/skole-store.ts` keeps classes, each code's choices + answers and a class list per teacher in the store under `skole/`, and deletes a class when its days are up. Classes made before teacher logins (secret link + hash of the e-mail) move to the teacher who signs up with that e-mail (`adoptLegacyClasses()`). When a calculation changes, update the step's "Hvorfor?" text in `steps()`. Locally the subdomain is `skole.localhost:3200` (Chrome resolves it; PowerShell does not, so test it with curl and a `Host` header).
- Env (`.env.local`): `RESEND_API_KEY` + `MAIL_FROM` (or `REMINDER_MAIL_FROM`) to send mail – without them dev shows the link on the page and in the server log; `AUTH_SECRET` (≥32 chars, else a random key in `data/auth-secret`); `APP_URL` for links (default: the request origin).

## Private data (the repo is public)

- Real budget data never goes into git: KBJ's budget is `public/private/kbj.legacy.json` (git-ignored), loaded by the app on a user's first visit when no saved data exists. `pnpm extract:app <Budget2027.html> kbj` regenerates the app and that file from the prototype – it overwrites `public/budgetr-app/index.html`, so only use it to start over.
- Saved budgets, accounts, profiles and the fallback session key go through `lib/kv.ts`: on disk in `data/` (`data/<userId>.json`, backups in `data/backups/<userId>/`, git-ignored), or in Upstash Redis when `KV_REST_API_URL` + `KV_REST_API_TOKEN` (or `UPSTASH_REDIS_REST_*`) are set – that is how it runs on Vercel (budgets: `lib/budget-file.ts`, route `app/api/budget/[user]`). `pnpm reminders` still only reads the disk. The app also keeps a localStorage copy; the disk copy wins unless the last save never reached it. Never delete `data/`.
- Never put real names, amounts, account numbers or e-mails in committed files, tests, docs or screenshots. Scan `public/budgetr-app/` before committing.

## Rules

- Explainer films: the front page, Erhverv and Skole each show their film right under the hero (`components/Film.tsx`: `public/video/budgetpro-<name>.mp4` with a poster `.jpg`, a frame from the intro; muted, loads on play). Each film also exists upright as a reel, `budgetpro-<name>-reel.mp4` + `-reel.jpg` (1080×1920, 9:16, also for social media); `Film` shows the reel below 768 px and the 16:9 film above. `.mp4` is in the file list of `lib/site-host.ts` / `lib/skole-host.ts`, so the subdomains serve it. After re-rendering a film, remake its poster: `ffmpeg -ss 3.5 -i public/video/budgetpro-<name>.mp4 -frames:v 1 -vf scale=1600:-1 -q:v 3 public/video/budgetpro-<name>.jpg` (reel: `-reel.mp4` → `-reel.jpg` with `scale=900:-1`).
- Landing design source of truth: layout from `docs/design/forside-v2.html` ("Forside v2", Sept 2026; its product mock-ups are replaced by real screenshots), colours and the light hero from `docs/design/midnat-forside.html` (Oct 2026) + the copy rules in `docs/design/HANDOFF.md`; the landing palette is the `.page` block in `components/landing/landing.module.css`.
- Films (Oct 2026): `video/erhverv.html` (48 s), `video/privat.html` (51 s) and `video/skole.html` (56 s: a class in two minutes, then the four lessons with their features, then following the class; no code printing), text only, no sound, privat and erhverv in "Midnat og lime", skole in "Midnat og solgul" (`<html data-theme="skole">` swaps the accent variables in `film.css`; `data-sticker="Skole"` on a `[data-logo]` adds the Skole sticker). Shared runtime and styles in `video/film.js` / `video/film.css` (statement import scene, feature montage, cursor, and the motion graphics: `[data-logo]`/`[data-icon]` filled with the real logo, `buildLogo` – the cards drop into the pocket, `words`/`caption` – headlines word by word with a lime `.hl` underline, `curtain` – the dark intro lifts and the end card drops with a lime band, `darkBg` – drifting cards on the dark cards, `orb` – a lime circle moving between scenes, `enter` – 3D entrance of screenshots); each frame comes from `seek(t)`, so `pnpm video <erhverv|privat|skole>` renders an exact MP4 to `public/video/` (needs ffmpeg + Chrome; `--still=<s>` gives one PNG; `--reel` renders the 1080×1920 reel). The reel is the same page opened with `?reel` (`<html data-format="reel">`, `F.W`/`F.H` in film.js): caption on top, visual below, key content between y ≈ 220 and 1640 (clear of the app bars on reels); the shared intro/end/caption layout is the reel block at the end of `film.css`, each film places its own visuals in its `[data-format="reel"]` rules – when a film gets a new visual, place it there too and render both formats. Open a film's HTML in Chrome to preview it on a loop (`?t=12` starts at second 12). Keep their texts in step with the pages and the app; they use the landing/skole screenshots, so re-render after `pnpm shots`.
- Landing motion (the "Motion" block at the end of `landing.module.css`, all off with reduced motion): the hero title wipes up and its lime underline is drawn, the logo's cards drift behind the hero window and on the final call to action (`heroCards`, `ctaCards`, never over a screenshot), circles on the midnight bands breathe, `ScrollReveal` headlines wipe up out of a mask, `data-reveal="tilt"` (screenshots, film, price card) tilts up into place, and the photo banner pans slower than the page (scroll-driven CSS where supported). Never put the clip on an element that is itself observed by `ScrollReveal` – the IntersectionObserver then never sees it.
- The landing shows real screenshots of the app in both themes (`public/landing/`). After visible app changes, run `pnpm shots` with the dev server up; it renders the fictional budget in `scripts/demo-budget.mjs` (never real data) and touches nothing in `data/`.
- Brand is **budgetpro** ("Midnat og lime", Oct 2026; spec `docs/design/MIDNAT.md`, designmanual `docs/design/midnat-designmanual.html`, front page with the light hero `docs/design/midnat-forside.html`): the logo is a pocket with two cards (front card lime, back card + pocket midnight on light / white on dark) + "budget" Hanken Grotesk 700 and "pro" Hanken Grotesk 200 in the same colour, in `components/Logo.tsx` (`Logo`, `LogoMark`, `AppIcon`) and the app's `.logo`; Hanken Grotesk is only for the logo. Favicon `public/icon.svg` = the symbol on a midnight rounded square. Colours: midnight `#0E1B2C`, lime `#D4F26B` (text only on dark), olive `#3F6A0E` for accent text on light, page `#F3F5F7`; primary buttons are midnight pills on light and lime pills on dark; Geist for all other text (+ Geist Mono for KPI amounts). The app's copy of the palette is the `:root` block in `public/budgetr-app/index.html`; keep it in step with `app/globals.css` and the landing `.page` block. budgetpro Skole has its own variant "Midnat og solgul" (Oct 2026, `docs/design/skole-21b.html`): solgul `#F6CF4A` takes lime's place (`#7A5300` for accent text on light, warm page `#F5F5F0`, borders `#E2DFD8`), the logo is `SkoleLogo` in `components/Logo.tsx` (solgul front card + a solgul "Skole" sticker on the baseline of "pro"), favicon `public/skole/icon.svg`, palette in the `.page` blocks of `components/skole/skole.module.css` and `components/skole/landing/skoleLanding.module.css`.
